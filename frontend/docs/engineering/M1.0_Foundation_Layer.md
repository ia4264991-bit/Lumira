# Engineering Report — M1.0: Selection Engine Foundation Layer

**Status:** Complete
**Package(s):** `selection.model`, `selection.capture`, `selection.geometry`
**Depends on:** nothing outside `selection.*` (pure Kotlin except `selection.capture`, which is Compose-facing by necessity)
**Depended on by:** M1.1 (`selection.textlayout`), `ui.reader` (Reader screen integration)

---

## 1. Objectives

Implement the foundation layer of the previously-approved Selection Engine
design: the ability for a user to draw a freeform lasso over a rendered PDF
page, have that stroke captured, simplified, converted into a validated
polygon, and rendered live on screen — with **no** text extraction, polygon
intersection, selection generation, OCR, or backend communication in this
milestone. This milestone also introduced the `SelectionTool` enum
(`TEXT`, `LASSO`) into the Reader UI, designed so future tools can be added
as new enum constants rather than requiring a redesign.

## 2. Architectural Decisions

- **Canonical coordinate system**: every geometric object in the Selection
  Engine — from a raw touch point to a finalized polygon vertex —
  eventually converges on **normalized page-display space**, `(u, v) ∈
  [0,1]×[0,1]`, top-left origin, already rotation-corrected to match what's
  rendered on screen, independent of zoom level and device pixel density
  (`NormalizedPoint`). This is the single decision that keeps every later
  layer (text layout, future intersection) from needing to know about zoom,
  pan, or PDF page rotation.
- **Strict pure/impure layering**: `selection.model` has zero Android,
  Compose, or PDFBox imports — verified by direct scan, not just assumed.
  `selection.geometry` depends only on `selection.model`, `kotlin.math`, and
  `javax.inject` (for Hilt) — no Android/Compose dependency either. Only
  `selection.capture` (`LassoGestureController`) touches Compose, because
  gesture detection inherently requires it.
- **Gesture capture is a pure callback-driven detector, not a state holder**:
  `LassoGestureController` holds no Compose state itself; it reports
  captured points via callbacks, leaving the caller free to decide how to
  render them. This was deliberate to keep gesture-capture logic unit-testable
  in principle and decoupled from any specific rendering strategy.
- **Multitouch arbitration scoped down intentionally**: per the approved
  design, a second pointer touching down mid-stroke cancels the in-progress
  lasso rather than attempting simultaneous pinch-zoom-while-drawing.
  Pinch-zoom is paused entirely while `LASSO` mode is active (single-finger
  draw only) — a deliberate, documented scope cut for this foundation
  milestone, not a permanent limitation of the architecture.
- **Live-drawing performance**: the in-progress stroke is drawn via an
  imperative `androidx.compose.ui.graphics.Path` mutated directly inside
  gesture callbacks, with a single `Int` "version" counter as the only
  Compose-state read driving redraws. This avoids the classic Compose
  freehand-drawing trap of storing every point in a `List` inside
  `mutableStateOf`, which would cost O(n) recomposition as a stroke grows.
  The live-stroke canvas and the finalized-polygon canvas were each
  extracted into their own small composable (`LiveStrokeOverlay`,
  `PolygonOverlay`) so a redraw never ripples into the page `Image` or
  sibling UI.
- **Two coordinate spaces for two rendering concerns**: the in-progress raw
  stroke is drawn 1:1 in outer, untransformed viewport pixels (it must track
  the finger exactly, regardless of zoom); the finalized polygon is drawn
  inside the *same* `graphicsLayer` transform the page image uses, so it
  automatically pans/zooms with the page without re-deriving the pinch-zoom
  transform a second time. `CoordinateMapper`/`FittedRect` handle the
  reverse (screen → normalized) direction, composing an inverse pinch-zoom
  transform with an inverse `ContentScale.Fit` letterbox transform.
- **Zoom-relative simplification tolerance**: `StrokeSimplifier`'s
  Ramer–Douglas–Peucker tolerance is expressed in content-space terms and
  scaled by the current zoom level, so simplification behaves consistently
  whether the user drew at 1x or 4x zoom.

  scan of every file's import list.

  `kotlin.math`, `javax.inject`.
- Confirmed all three geometry classes (`StrokeSimplifier`,
  `CoordinateMapper`, `PolygonBuilder`) are `@Inject constructor()`-annotated
  and resolve through Hilt with zero new modules, consistent with the
  existing `PdfTextExtractor` pattern already in the codebase.
- Confirmed every `ReaderUiState.copy(...)` call site handles the two new
  fields correctly (no stale-polygon leakage across tool switches or page
  navigation).
- Confirmed `NavGraph.kt` required no changes (public `ReaderScreen`
  signature identical to before).
- Confirmed zero references to any selection-engine type leaked into
  `data/`, `di/`, `ui/auth/`, `ui/account/`, or `ui/navigation/`.
- Confirmed no duplicate type/class definitions anywhere in the project for
  any name introduced this milestone.
- Project-wide unused-import scan across every touched file: clean.
- Corrected during audit: a missing `awaitFirstDown` import in
  `LassoGestureController`; an invalid `@Suppress` placement on a bare
  expression statement (replaced with a `@Suppress`-annotated `val`); a
  `Float.MIN_VALUE` sentinel bug in `SelectionPolygon.boundingBox()`
  (smallest *positive* float, not a large-negative sentinel — corrected to
  `Float.NEGATIVE_INFINITY`/`POSITIVE_INFINITY`); a redundant `viewportSize`
  Compose state duplicating `PointerInputScope.size` already available in
  the same gesture closure (removed).
- No live Gradle/compiler build was possible in this sandbox (no access to
  Google's Maven repository); all verification was via direct source review
  and targeted static analysis.

## 6. Known Limitations

- Pinch-zoom is paused while `LASSO` mode is active — full simultaneous
  pinch-zoom-between-strokes arbitration described in the approved design is
  deferred past this foundation milestone.
- No text extraction, polygon–text intersection, or selection generation
  exists yet — `selection.textlayout` and `selection.engine` were reserved
  but empty at the close of this milestone.
- `LassoGestureController`'s gesture-detection logic itself is not
  unit-testable in isolation (inherent to Compose's pointer-input APIs);
  `StrokeThinner`, `StrokeSimplifier`, `CoordinateMapper`, and
  `PolygonBuilder` are all pure and fully unit-testable, which was a
  deliberate goal of the layering.

## 7. Risks

- Without a live build in this sandbox, there was residual risk of a
  Material3 `SegmentedButton`/`SegmentedButtonDefaults.itemShape` API-surface
  mismatch against the exact Compose BOM version — flagged as the first
  thing to check on initial Android Studio sync.
- The coordinate-mapping math (pinch-zoom inversion composed with
  `ContentScale.Fit` letterbox inversion) was logically verified but not yet
  validated against real on-device touch input.
